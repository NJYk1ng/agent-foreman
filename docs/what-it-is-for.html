agent-foreman

让「做完了」
变得可证伪

一个 AI 单独干活，最大的毛病不是干得差，是它会说「我做完了」—— 而你没有证据反驳。这个项目不解决「怎么让 AI 更聪明」，它解决的是 「凭什么信它」。

github.com/NJYk1ng/agent-foreman · Apache-2.0 · 已被三轮真实任务打磨

它是什么

不是多 agent 框架。是一套让两个 AI 互相盯着的规矩。

两个 agent 不直接通信，只通过项目里 .foreman/ 的四个文件交接： PLAN（领导写）、STATUS（工人写）、 BLOCKED（工人写）、REVIEW（领导写）。 谁说什么、什么算做完了、谁有权说「通过」——全在这四份文件里定死。

骨架：三种「不知道」要分开

大部分 AI 协作翻车，是把三种完全不同的「不知道」混成了一锅。 这个项目的核心装置，就是把它们分开，并且明确谁有资格判哪一种。

机器可验 只有人在场能验
[命令]

跑一下就知道

写得出命令、比得了输出。文件在不在、有没有外链、语法过不过。

谁都能验 → 工人自证，领导重跑
[观察]

看个能观察的事实

有具体数值或可 grep 的引文。「实测 32.1Hz」「日志第 142 行」。

谁都能验 → 但「我读过第 2 节」不算证据
[现场]

只有人在场能判

像不像、好不好看、现场那几秒顺不顺。写不出命令，也观察不了。

只有人能验 → 两个 AI 都不许碰

[现场] 那一条是整套东西的关键。工人没有眼睛，领导也没有眼睛—— 谁说「通过」都是耍流氓。所以规矩是：谁都不许判，只能写 ⏳ 待现场验证，把复现步骤写细到照着做就行，交给人。

分工：贵的只花在判断上

前提挺现实：Claude 在中国会封号、还贵；Codex 管得松，但订阅是硬上限； DeepSeek 便宜。所以按「需要什么」分，而不是按「谁更聪明」分。

领导 · Codex

  • 拆需求、写验收标准
  • 审工人的产出、独立复核
  • 工人卡住时给方向
  • 不做实现

工人 · Claude Code

  • 按 PLAN 实现
  • 逐条自证、贴真实输出
  • 写 STATUS 汇报
  • 卡住写 BLOCKED，不硬撑

工人干完活会自动把领导叫醒。领导醒来的第一件事不是干活，是问人： 

工人交了 .foreman/STATUS.md：T1 标为 UNVERIFIED，AC1 已通过，
AC2–AC4 待你现场验收。要我现在审查吗？

你说「审」它才动手。花领导额度的动作，永远有人按过手印。

能指望它什么

一、把「agent 说自己做完了」换成「证据说话」

工人必须贴真实命令输出，不许复述、不许概括。领导必须 自己把每一条重跑一遍，不许采信。

实测有效：某轮工人贴了 6 个命令块，领导只重跑了 1 条就给了通过。 把「每一条都要自己重跑」写进规矩之后，下一轮它跑满了 6 条， 还专开一节记录复核过程——腿部运动学采样 10000 个相位，比工人自己还狠。

二、角色和边界长在 agent 身上，不用每次交代

跑一次 ./install.sh，两个 agent 的全局记忆里就写进了 「你该干什么、不该干什么、什么情况下完全不用管这套」。

实测：需求方只说了一句「读 REQUIREMENT.md，出 PLAN」， 没告诉它「你是领导」——它自己认出了这是 agent-foreman 流程， 自己去读了对应 skill，自己写出了计划。

三、判不了的事，它会说判不了

T1/AC1 [命令]  ✅ 已独立复现
T1/AC3 [现场]  ⏸ 领导无法独立判定 —— 需求方已验通过，记录在 STATUS.md

一个不肯说「我证不了」的系统，你没法信它说的任何一句「通过了」。

规矩是踩出来的，不是想出来的

下面五条全部来自真实任务翻车后的复盘。每一条都有原话、有现场记录， 写进了 契约 和对应的 skill 里。

  1. 01证据要可独立核对，章节指针不算证据第一次闭环
  2. 02人闸还要求可见性第一次闭环
  3. 03不许用「留痕」替代「验证」pelican-bike 第 1 轮
  4. 04工人贴的每一条命令，领导都要自己重跑pelican-bike 第 2 轮
  5. 05两种「无法判定」要分开写，别让人以为他还没验pelican-bike 第 3 轮

第 3 条是个好例子：工人把「断网也能打开」记成了通过， 只在旁边加了句备注说「不确定有没有真断网试过」。 领导打回了，原话是「应记为无法判定，不能据此标为 DONE」—— 备注是写给自己看的，勾是写给对方看的。

它不适合什么

验收标准说不清的任务 写小说、做设计、调手感——判据在人眼，[命令] 那一级根本立不起来。
一个 agent 就够的小活 上一整套是负担，不如直接干。
需要实时商量的事 它是异步的，靠文件交接，不是对话。

说清楚哪里还不顺手

工人被叫醒那一侧，现在每轮要人敲一下。这是刻意留的。

自动叫醒试过两条路，都放弃了：文件监听有个已知缺陷——agent 一跑 cd 命令，监听就被悄悄解除，而且不报错； 另一条要走 Claude Code 内部未公开的套接字协议，逆向出来下次升级就可能静默失效。

每轮敲一下的代价是两三秒，换来的是这套东西永远不会哪天偷偷不灵。 完整理由写在 README 里。

它不让你更快，它让你更敢信。
